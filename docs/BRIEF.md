# 프로젝트 브리프 — 도란도란 (구 가칭: 리딩버디)

**문서 버전:** v1.3  
**작성일:** 2026-09-12 (최종 갱신: 2026-09-13)  
**상태:** MVP + 확장 기능 개발 완료 및 공식 브랜딩('도란도란') 적용, 프로덕션 운영 중 (https://reading-buddy-ten.vercel.app)

> 이 문서는 프로젝트를 처음 접하는 사람이 5분 안에 "무엇을, 왜, 누구를 위해 만들었는가"를 파악하도록 돕는 요약 문서다. 요구사항의 전체 배경과 결정 과정은 [PRD.md](PRD.md), 기술 구조의 상세는 [ARCHITECTURE.md](ARCHITECTURE.md), 기능 단위 상세는 [STORIES.md](STORIES.md)를 참고할 것.

## 1. 한 줄 요약

초등 3학년 쌍둥이 자녀가 대화와 사진 촬영만으로 독서 기록을 남기고, 부모는 그 기록을 검토해 '독서로'(국가 독서 기록 사이트)에 반영할 수 있게 돕는 가족용 PWA.

## 2. 문제

- 학교/지자체가 요구하는 독서 기록 사이트 **'독서로'(read365.edunet.net)**는 PC 중심 UI라 초등 저학년 아이가 혼자 쓰기 어렵고, 매번 부모의 도움이 필요하다.
- 독서 감상문을 **텍스트로 직접 쓰는 것** 자체가 아이에게 부담스러운 작업이라, 실제로 읽은 책의 양에 비해 기록으로 남는 양이 훨씬 적다.
- 학교 종이 독서노트에 이미 써둔 기록도 있지만, 그 내용이 '독서로'에는 다시 반영되지 않아 이중 작업이 되거나 아예 누락된다.

## 3. 해결 방향

아이가 부담 없이 참여할 수 있는 두 가지 입력 방식을 제공하고, 모인 기록을 부모가 검토해 '독서로'에 반영하는 흐름을 지원한다.

1. **대화형 기록**: 앱이 단계별로 질문을 던지고(장면 소환 → 역할 바꾸기 → 현실 적용), 아이는 말하거나 타이핑으로 답하기만 하면 AI가 3단 구성의 감상문을 완성한다.
2. **독서노트 사진 촬영**: 종이에 이미 써둔 독서노트를 사진 찍으면 OCR로 텍스트를 추출해 구조화된 기록으로 바꿔준다.

'독서로' 반영은 이용약관상 자동화(크롤링) 허용 여부가 불확실해 **완전 자동화 대신, 복사·바로가기·완료 체크로 이어지는 수동 등록 가이드**로 구현했다(9절 및 PRD 참고).

## 4. 타겟 사용자

| 구분 | 설명 |
|---|---|
| **아이 (기록 주체)** | 초등 3학년 쌍둥이. PC 사용은 서툴지만 모바일 터치·음성 인터페이스에는 익숙. 로그인 계정 없이 부모 계정 아래 프로필(PIN)로 존재 |
| **부모 (관리자)** | 유일한 정식 로그인 주체. 자녀 프로필 생성/관리, 기록 검토·수정, '독서로' 반영 상태 관리, 독서 통계·배지 확인 |

## 5. 목표와 성공 지표

- 아이가 모바일에서 스스로 기록을 남길 수 있게 한다 (부모 개입을 '작성 대행'에서 '검토'로 낮춘다)
- 실제 독서량과 기록량의 격차를 줄인다
- 운영 비용은 합리적 수준 유지: Supabase 무료 티어 + Azure 구독 월 $150 예산 내 운영

성공 지표(안): 아이 1인당 주간 기록 등록 건수, '독서로' 반영률, 부모의 수동 타이핑 개입 빈도 감소, 아이의 자발적 사용 빈도. (상세: PRD 2.2)

## 6. 범위

### 포함 (구현 완료)

- 부모 회원가입/로그인, 자녀 프로필 생성·PIN 전환, 아바타(이모지/사진)
- 대화 기반 독서 기록 (텍스트+음성, 책 정보 조회 연동, 단계별 질문 프레임워크, AI 감상문 생성, 부모의 질문 스타일 커스터마이즈)
- 독서노트 OCR 입력 (사진 → 구조화 → 수정 → 저장)
- 표지 사진으로 책 자동 검색 (OCR + AI 추정 + 후보 선택)
- '독서로' 수동 등록 가이드 (복사/바로가기/완료 체크)
- 기록 관리 (본인 히스토리, 부모 대시보드, 검색·무한 스크롤, 페이지 수 기록)
- 독서 통계 리포트, 형제자매 배지·비교
- Vercel 배포 및 자동 재배포
- 태블릿/PC 반응형 레이아웃(전 화면), 프리텐다드(Pretendard) 폰트

### 제외 (의도적 보류)

- '독서로' 완전 자동 등록(크롤링/Playwright) — 이용약관 확인 전까지 보류
- 네이티브 앱 전환, 다른 챕터(숙제 기록 등) 확장 — 로드맵으로만 존재
- 장르 분포 통계 — 스키마에 장르 컬럼이 없어 범위 밖으로 판단

## 7. 핵심 설계 결정 (요약)

| 결정 | 이유 |
|---|---|
| Supabase(Postgres+Auth+Storage), 무료 티어 | 관계형 가족 데이터 구조에 적합, RLS로 DB 레벨 접근 제어 가능 |
| 자녀는 별도 계정 없이 PIN으로 프로필 전환하되, 내부적으로는 synthetic 계정의 **실제 Supabase Auth 세션**을 발급 | 자매 앱 `twin_choice` 패턴 재사용 — RLS가 "누구의 프로필인가"까지 DB 레벨에서 강제 가능 |
| Azure OpenAI 하이브리드(질문 생성=경량 모델, 감상문 생성=상위 모델) | 대화는 응답 속도, 감상문은 세션당 1회라 품질 우선 |
| '독서로' 자동화 대신 수동 등록 가이드 | 공공 교육 플랫폼의 크롤링 허용 여부 미확인 — 리스크 회피 |
| 호스팅은 Vercel(Azure Static Web Apps 아님) | 사용자 선택, Next.js와의 배포 통합이 단순함 |
| 도서 검색은 카카오 단독 → 카카오+도서관정보나루 병행 | 네이버(2026-07-31)·알라딘(2026-10-30) 도서 검색 API가 잇달아 서비스 종료되어 공공데이터로 대체 |

상세 배경은 [PRD.md](PRD.md) 6장·8장, 기술 구조는 [ARCHITECTURE.md](ARCHITECTURE.md) 참고.

## 8. 현재 상태

- **Phase 1 (MVP, 5개 항목)**: 계정/인증, 대화 기반 기록, OCR 입력, 독서로 연동(수동 가이드), 기록 관리 — 전부 구현 및 실제 브라우저 테스트 완료
- **Phase 2 (확장 4개 항목)**: Vercel 배포, 독서 통계, 표지 촬영 인식, 형제자매 배지 — 전부 구현 및 검증 완료
- **품질 개선**: API 라우트 자녀 전용 가드 보강, 유닛 테스트 54개 도입(Vitest), 페이지 전환 속도 개선(리전 고정·병렬 조회·중복 인증 제거), 죽은 스키마(`dokseoro_credentials`) 정리
- **지속적인 사용자 피드백 반영**: 책 제목 자동완성, AI 질문 코치 프리셋, 기록 목록 무한 스크롤/검색/날짜 필터 + 자녀별 탭(탭 선택 유지 버그 수정 포함), 음성 인식 수정(PCM WAV 인코딩), 감상문 검수 화면(원본 답변 비교·쓰기 팁), AI 질문의 책 내용 그라운딩 강화, 답변이 부실할 때의 팔로업 질문, 책 페이지 수 필수 입력 + 검색 도우미 링크, 전 화면 태블릿/PC 반응형 레이아웃, 프리텐다드 폰트 교체, AI 질문 스타일 화면 다듬기(저장 전 미리보기·글자 수 표시·미저장 경고·팔로업 동작 안내), **공식 명칭 '도란도란' 확정 및 PWA 아이콘/파비콘 에셋 적용**
- 프로덕션 URL: **https://reading-buddy-ten.vercel.app**

세부 구현·검증 이력은 저장소 루트의 [CLAUDE.md](../CLAUDE.md)가 살아있는 소스로 관리한다.

## 9. 주요 리스크

- **'독서로' 이용약관상 자동화 허용 여부 미확인** — 확인 전까지 완전 자동 등록 미구현
- **무료 도서 검색 API의 서비스 종료** — 네이버·알라딘이 이미 종료(예정)되어 카카오+공공데이터로 재구성함. 카카오도 동일 리스크에서 자유롭지 않음
- **Supabase 무료 프로젝트의 7일 비활성 자동 일시정지** — 방학 등 공백기 대비 정기 핑 장치 필요(미구현)
- 상세: [PRD.md](PRD.md) 7절
