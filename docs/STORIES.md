# 사용자 스토리 — 리딩버디 (Reading Buddy)

**문서 버전:** v1.3
**작성일:** 2026-09-12 (최종 갱신: 2026-09-13)

> 이 문서는 [PRD.md](PRD.md)의 요구사항을 실제 구현 단위(에픽/스토리)로 분해해 정리한 것이다. 모든 스토리는 **이미 구현·실제 브라우저(또는 curl/SQL)로 검증 완료**됐다 — 상태 표시가 없는 스토리는 없다. 신규 기능을 계획할 때는 이 문서에 새 에픽/스토리를 추가하는 방식으로 갱신할 것. 각 스토리의 구현 상세·검증 내역은 저장소 루트의 [CLAUDE.md](../CLAUDE.md)를 참고.

역할 표기: **부모** = 유일한 정식 로그인 주체, **자녀** = PIN으로 전환하는 프로필(실제로는 synthetic 계정 세션).

## 에픽 1. 계정/인증

### US-1.1 부모 회원가입/로그인
- **As a** 부모, **I want to** 이메일/비밀번호로 가입하고 로그인, **so that** 내 가족 공간을 만들고 계속 접근할 수 있다.
- 인수 조건: `/signup`에서 가입 시 `families` row와 `join_code`가 함께 생성된다 / `/login`에서 로그인 실패 시 명확한 오류 메시지 / 세션은 미들웨어가 매 요청 갱신
- 상태: ✅ 완료 (`src/app/signup`, `src/app/login`, `src/app/api/auth/*`)

### US-1.2 자녀 프로필 생성 및 PIN 설정
- **As a** 부모, **I want to** 자녀 이름과 4자리 PIN으로 프로필을 만들고, **so that** 아이가 로그인 없이 본인 프로필로 들어올 수 있다.
- 인수 조건: 이름 필수, PIN 4자리 숫자, PIN은 해시로 저장(평문 없음) / 등록 시 사진 업로드도 가능(선택)
- 상태: ✅ 완료 (`/profiles/new`, `src/app/api/children/route.ts`)

### US-1.3 프로필 선택 → PIN 입력 → 세션 전환
- **As a** 자녀, **I want to** 내 프로필 카드를 고르고 PIN을 입력해, **so that** 내 기록 화면으로 바로 들어갈 수 있다.
- 인수 조건: 프로필 카드는 이름+아바타로 큼직하게 표시 / PIN 4자리 입력 후 **확인 버튼**을 눌러야 제출(자동 제출 아님, US-1.7 참고) / 성공 시 synthetic 계정으로 실제 Supabase Auth 세션 발급, `/home`으로 이동
- 상태: ✅ 완료 (`/profiles`, `/profiles/[id]/pin`, `src/lib/childAuth.ts`)

### US-1.4 PIN 실패/잠금 처리
- **As a** 시스템, **I want to** PIN을 5회 연속 틀리면 1분간 잠그도록, **so that** 무차별 대입 시도를 기본 수준에서 막을 수 있다.
- 인수 조건: `profiles.pin_fail_count`/`pin_locked_until` 갱신 / 잠금 중에는 남은 시간 안내 / 잠금 해제 후 재시도 가능
- 상태: ✅ 완료 (`src/lib/childAuth.ts`의 `PIN_MAX_ATTEMPTS`/`PIN_LOCK_DURATION_MS`)

### US-1.5 부모 설정에서 자녀 이름/아바타/PIN 수정
- **As a** 부모, **I want to** 자녀 프로필을 나중에 수정, **so that** 이름 변경이나 PIN 분실에 대응할 수 있다.
- 인수 조건: `/settings/children`에서 이름·아바타(이모지 또는 사진) 수정, PIN 재설정 가능
- 상태: ✅ 완료 (`/settings/children`, `ChildEditCard`)

### US-1.6 자녀 얼굴 사진을 아바타로 사용
- **As a** 부모, **I want to** 이모지 대신 아이 얼굴 사진을 아바타로 올리고, **so that** 프로필을 더 쉽게 구분할 수 있다.
- 인수 조건: 비공개 스토리지 버킷(`avatars`)에 `{family_id}/{profile_id}` 경로로 upsert 저장 / 화면 노출은 매번 새로 발급한 서명 URL(TTL 7일)로 처리 / 사진 제거 시 스토리지 파일도 실제 삭제 / 재업로드 시 이전 파일이 안 남음
- 상태: ✅ 완료 (`src/lib/avatarPhoto.ts`, `0007_avatar_photo.sql`) — 8개 화면에 서명 URL 반영, JPEG→PNG 재업로드까지 실제 브라우저로 검증

### US-1.7 PIN 화면에 확인 버튼 추가 (응답 지연 체감 개선)
- **As a** 자녀/부모, **I want to** PIN 4자리를 다 누른 뒤 확인 버튼을 눌러야 진행되도록, **so that** "눌렀는데 되는 건지 안되는 건지" 헷갈리지 않는다.
- 인수 조건: 로그인 PIN, 자녀 등록 PIN 설정, PIN 재설정 세 화면 모두 자동 제출 대신 공용 `PinConfirmButton` 사용 / 처리 중에는 버튼 라벨이 "확인하는 중..."/"만드는 중..."으로 바뀜
- 상태: ✅ 완료 (`src/components/PinKeypad.tsx`)

### US-1.8 자녀 등록 화면에서 바로 사진 업로드
- **As a** 부모, **I want to** 자녀를 처음 등록하는 화면에서 바로 사진을 올릴 수 있게, **so that** 등록 후 다시 수정 화면을 열지 않아도 된다.
- 인수 조건: 프로필 생성 전에는 `URL.createObjectURL`로 미리보기만 표시 / PIN 확인 후 프로필이 실제로 생성된 다음 스토리지 업로드+기록 / 업로드 실패해도 프로필 생성 자체는 막지 않음
- 상태: ✅ 완료 (`/profiles/new`)

### US-1.9 자녀 프로필 삭제
- **As a** 부모, **I want to** 더 이상 필요 없는 자녀 프로필을 완전히 삭제, **so that** 잘못 만든 프로필이나 탈퇴 요청에 대응할 수 있다.
- 인수 조건: 삭제 전 "되돌릴 수 없다"는 경고 + 취소/확인 2단계 / 삭제 시 synthetic 계정 삭제로 프로필·대화·기록·OCR 업로드까지 cascade 삭제 / 아바타 스토리지 파일은 별도로 먼저 삭제
- 상태: ✅ 완료 (`DELETE /api/children/[id]`) — DB/Storage/auth.users 전부 삭제됨을 REST API로 검증

## 에픽 2. 대화 기반 독서 기록

### US-2.1 책 정보 입력 후 대화 시작
- **As a** 자녀, **I want to** 책 제목(+저자)을 입력하고 대화를 시작, **so that** 그 책에 대한 질문을 받을 수 있다.
- 상태: ✅ 완료 (`/read/new`, `/read/new/book`)

### US-2.2 단계별 독서록 유도 질문 (장면 소환 → 역할 바꾸기 → 현실 적용)
- **As a** 자녀, **I want to** 4개의 질문에 순서대로 답하면, **so that** 단순 문답이 아니라 독서록 작성 능력 자체가 길러진다.
- 인수 조건: 1단계 "장면 소환"(2문항, 사건→행동/줄거리 확인) → 2단계 "역할 바꾸기"(공감·"나라면") → 3단계 "현실 적용"(자기 생활 연결)으로 고정 매핑 / 진행 표시에 단계 라벨 노출("장면 소환 · N/4 질문") / 두 번째 질문부터 아이 답변에 공감 후 다음 질문
- 상태: ✅ 완료 (`src/lib/readingSession.ts`의 `STAGE_PLAN`, `src/lib/azureOpenAI.ts`의 `generateNextQuestion`)

### US-2.3 책 정보(줄거리)를 반영한 구체적인 질문
- **As a** 자녀, **I want to** 책의 줄거리를 아는 AI가 더 구체적인 질문을 해주면, **so that** 형식적인 질문보다 몰입해서 답할 수 있다.
- 인수 조건: 카카오(+도서관정보나루) 도서 검색으로 줄거리 요약을 조회해 질문 생성 프롬프트에 포함 / 조회 실패 시 에러 없이 제목/저자만으로 폴백 / 채팅 화면에서 "📖 참고한 책 정보 보기"로 확인 가능, 못 찾았으면 안내 문구 표시
- 상태: ✅ 완료 (`fetchBookContext`, `ChatSession`)

### US-2.3.1 질문이 실제 책 내용을 반영하도록 그라운딩 강화
- **As a** 자녀, **I want to** 매번 다른 책에도 똑같이 통하는 뻔한 질문 말고, 이 책 얘기라는 게 분명한 질문을 받고 싶다, **so that** 실제로 이 책을 읽었다는 게 질문에서부터 느껴진다.
- 인수 조건: 시스템 프롬프트가 줄거리 요약에 나온 구체적 사건/인물 이름을 최소 하나는 넣도록 강제 / 단계별 지침이 완성된 질문 문장 대신 "구체성을 요구하는 지시"로 구성돼 매번 다른 질문이 나옴 / 요약이 줄거리가 아니라 "OO주년 기념 개정판" 같은 출판 마케팅 문구뿐이면 그 문구를 무시하고 모델이 아는 지식으로 대체(유명하지 않은 책은 제목만으로 자연스럽게 질문)
- 상태: ✅ 완료 (2026-09-12, 사용자 피드백 "질문이 책의 내용과 상관없이 진행되는 거 같아" 반영) — `src/lib/azureOpenAI.ts`, `src/lib/readingSession.ts`

### US-2.3.2 답변이 부실하면 AI가 한 번 더 캐묻기
- **As a** 자녀, **I want to** "몰라"처럼 대충 답해도 AI가 그냥 넘어가지 않고 다정하게 다시 물어봐주면, **so that** 부실한 답변으로 부실한 감상문이 나오는 걸 막을 수 있다.
- 인수 조건: 짧거나(3자 이하) 흔한 회피성 답변("몰라"/"글쎄"/"패스" 등)을 AI 호출 없이 코드에서 즉시 판정 / 같은 단계에서 혼내는 느낌 없이 다정하게 다시 캐묻는 팔로업 질문, 단계당 최대 1회 / 팔로업 질문·답변은 감상문 조립 시 해당 단계 답변 풀에는 포함되지만 "4문항 진행" 카운트에는 포함되지 않음 / 진행 표시에 "· 조금 더 자세히 들려줄래?" 안내
- 상태: ✅ 완료 (2026-09-12, 사용자 피드백 "AI 개입이 더 적극적이면 좋겠다" 반영) — `isAnswerTooShort`, `MAX_FOLLOW_UPS_PER_STAGE`, `next-question` 라우트

### US-2.3.3 AI 질문 스타일 화면에 팔로업 안내 추가
- **As a** 부모, **I want to** 질문 수가 항상 4개는 아니라는 것과 그 이유를 설정 화면에서 바로 알고 싶다, **so that** 지침을 바꿀 때 팔로업 동작까지 감안해서 이해할 수 있다.
- 인수 조건: `/settings/coach`에 "보통 4개 진행되지만 답변이 짧으면 같은 단계에서 한 번 더 캐물어 4개보다 많아질 수 있다"는 안내 박스 표시 / 팔로업 질문의 말투는 이 화면의 지침으로 못 바꾼다는 점도 명시 / 각 단계 라벨에 "질문 N개" 표시
- 상태: ✅ 완료 (2026-09-12, 사용자 피드백 "질문에 무조건 4단계를 유지하는 건 아니라고 했었는데, AI 질문 스타일에는 그 내용이 알 수가 없어")

### US-2.4 음성으로 답변
- **As a** 자녀, **I want to** 타이핑 대신 말로 답할 수 있게, **so that** 입력 부담 없이 대화에 참여할 수 있다.

### US-2.6.1 감상문 검수: 읽기 확인 + 원본 답변 비교 + 문장 쓰기 팁
